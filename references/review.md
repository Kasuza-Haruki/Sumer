# Review

spawn 一个只读、独立 review subagent。不要主线自审，不要 fork。

## 范围

| 场景 | 审什么 |
|---|---|
| 指挥方 | 改动涉及的前后端工作树 |
| 前端执行方，纯前端任务 | 本工作树自己的 diff |

纯前端任务不能跳过 review；来自 `[dispatch:` 且派活消息写明指挥方 review 时不重复。

## 输入

工作树、分支、diff 范围；相关 `AGENTS.md` 和 `docs/`。样式问题只看是否破坏现有规范，不作为 P0。规则以本文件和 `AGENTS.md` 为准，不读外部提示词文件。

## 提示模板

```text
你是独立只读 review agent。不要改文件、不要 commit/push、不要启动服务、不要连数据库、不要发外部请求。

先确认范围：
git -C <worktree> branch --show-current
git -C <worktree> status --short
git -C <worktree> diff --stat
<有前端改动时同样检查前端工作树>

要求同分支但分支不一致，或工作区没有本次改动，停止并说明。

只报 P0：崩溃、数据丢失或错写、鉴权/权限绕过、核心主流程不可用、前后端契约不一致导致主流程失败、真实费用或外部写入错误。
样式、命名、性能、边角、重构建议不算 P0。

输出：
P0: <无 | 列表>
- file:line | 影响 | 最小修复
P1+（只报告，不修）: ...
```

## 处理

只修 P0，P1+ 写进交付。只跑一轮；修完做针对性验证，不复审。P0 修复面大或风险高时停下问用户。
