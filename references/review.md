# Review

spawn 一个只读、独立 review subagent。不要主线自审，不要 fork。

## 范围

| 场景 | 审什么 |
|---|---|
| 指挥方，有前端改动 | 后端工作树 + 前端工作树，并逐项做前端 review 清单 |
| 指挥方，只有后端改动 | 后端工作树 |
| 前端执行方，纯前端任务 | 本工作树自己的 diff + 前端 review 清单 |

只要本次改了前端，review 就不能只审后端。纯前端任务不能跳过 review；来自 `[dispatch:` 且派活消息写明指挥方 review 时不重复。

## 前端 review 清单

逐项检查，违反任一项即为 P0：

1. 是否先读并遵守仓库 `AGENTS.md` 和 `docs/` 的设计规范。
2. 是否复用现有组件和 Token；不得自造样式体系或新增未经约定的值。
3. 规范缺失、样式冲突或不确定时，是否向用户提出并对齐；不得自行决定。

清单内化在本文件，不读外部提示词文件。

## 输入

工作树、分支、diff 范围；相关 `AGENTS.md` 和 `docs/`。规则以本文件、`AGENTS.md` 和 `docs/` 为准。

## 提示模板

```text
你是独立只读 review agent。不要改文件、不要 commit/push、不要启动服务、不要连数据库、不要发外部请求。

先确认范围：
git -C <worktree> branch --show-current
git -C <worktree> status --short
git -C <worktree> diff --stat
<有前端改动时同样检查前端工作树>

要求同分支但分支不一致，或工作区没有本次改动，停止并说明。

先读后端和前端仓库的 AGENTS.md，以及本次改动相关的 docs/。

前端 review 清单（有前端改动时逐项检查）：
1. 是否遵守 AGENTS.md 和 docs/ 的设计规范。
2. 是否复用现有组件和 Token；有没有自造样式或新增未经约定的值。
3. 规范缺失、冲突或不确定时，是否向用户提出；有没有自行决定。

只报 P0：
- 崩溃、数据丢失或错写、鉴权/权限绕过、核心主流程不可用、前后端契约不一致导致主流程失败、真实费用或外部写入错误。
- 违反 AGENTS.md 或 docs/ 明确约束的问题，包括组件、Token、样式、目录、命名、权限、流程。

仅属偏好、未违反明确约束的性能、边角、重构建议不算 P0。

输出：
P0: <无 | 列表>
- file:line | 影响 | 违反的规范 | 最小修复
P1+（只报告，不修）: ...
```

## 处理

只修 P0，P1+ 写进交付。只跑一轮；修完做针对性验证，不复审。P0 修复面大或风险高时停下问用户。

修复后保留原始问题：原文、依据、影响、修复方式一起交给交付汇报，不要只写“已修复”。
