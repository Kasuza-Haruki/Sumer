# E2E

固定环境：后端 18001，前端 15173；前端用仓库约定的 e2e 配置（如 `vite.e2e-local.config.ts`）把 `/api` 代理到 18001。不要用普通 dev 端口替代。

## 授权与复用

服务已在跑且两端分支相同：直接复用，不再授权；不重启、不改端口。

需要自己启动服务或连本地库：先给命令和副作用，问一次；自己启动后的点击测试含在同一次授权里。

只复用本分支。不同分支、其他工作树或归属不明：报告冲突，不换端口、不停别人的进程、不冒用；归属不明问用户一次。

## 启动

```bash
# 后端：用后端仓库根的 .venv（worktree 内通常没有）
cd <后端工作树>
<后端仓库根>/.venv/Scripts/python.exe manage.py runserver 18001

# 前端
cd <前端工作树>
pnpm exec vite --config <e2e 配置> --port 15173 --strictPort
```

`.venv` 在后端仓库根；worktree 缺 `.env` 时报告阻塞，不复制或打印内容。e2e 配置名以 `AGENTS.md` 或 `docs/` 为准，查不到就报告。

## 点击测试

1. 运行 `ego-browser skill`，按输出操作。
2. 用 `taskSpace("<当前分支名>")` 建或复用任务空间，分支名取 `git branch --show-current`；再打开 `http://127.0.0.1:15173`，进入需求对应页面，不只开首页。Page 标签固定为 `p1`/`p2`，用任务空间名区分分支。
3. 只测主路径加一条基本回归；不做全量矩阵。需要登录请用户在 ego-browser 里登录，不猜账号。
4. 记录点击、预期、实际。测试后停在结果页，不关闭页面和进程，留给用户查看和下次复用。

没有可点击路径就写“不适用”并给替代验证。未执行或失败写“未执行 E2E”及原因，不声称通过。
